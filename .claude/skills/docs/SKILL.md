# Docs

`docs/` is the reference manual for the four .hack PS2 games: what the formats
are, how the engine works, what is on the discs. It is written for someone who
wants to write a parser or a subsystem and does not care how we found out.

The worklog (see the `worklog` skill) is the other half. Worklog says *how we
found out* and *why*; docs says *what is true*, flatly, in its final form. When
a worklog entry establishes a format, the same session writes or updates the
docs page for it. A format is not documented until both exist.

## Layout

```
docs/README.md                index - generated by tools/docs.py index
docs/disc/layout.md           the DVD: file system, boot, what sits where
docs/formats/data-bin.md      one page per container or record format
docs/formats/prg.md
docs/engine/overlays.md       one page per subsystem
docs/engine/memory-map.md
docs/content/inventory.md     what is on the discs, with counts
```

Filenames are lower-case, hyphenated, and named after the thing, not the
session: `data-bin.md`, not `archive-notes-2.md`.

The sections are fixed in `tools/docs.py` (`SECTIONS`). A page in a folder that
is not listed there does not reach the index; add the section first.

## Every page starts with front matter

```markdown
---
title: The DATA.BIN archive
status: solid | partial | guess
volumes: INF | INF, MUT | all
covers: INF DATA/DATA.BIN, INF SLUS_202.67:0x00123456
worklog: 3, 7
---
```

`status` is the honesty knob and it is the most important field on the page:

| status | means |
| --- | --- |
| `solid` | round-trips, or every field is accounted for across every sample |
| `partial` | parses, but named fields remain unknown or unverified |
| `guess` | a hypothesis written down so the next session can attack it |

Downgrade a page the moment a sample breaks it. A `solid` page that is wrong
costs more than no page.

`volumes` says which of the four games the page has been checked against, by
tag: `INF`, `MUT`, `OUT`, `QUA`, or `all`. A format that looks shared is only
shared once each volume has been checked; until then list the ones that were.
`status` is a claim about the listed volumes and no others.

`covers` names what the page describes, with the same locators the worklog
uses: disc paths, archive members after `::`, and VAs in the executable or an
overlay.

`worklog` lists the entry numbers that established the page, comma separated,
so the reference points back at the evidence.

## A format page

Lead with the layout. A reader should be able to write the parser from the first
screen and read the prose only when something surprises them.

````markdown
# The DATA.BIN archive

One sentence saying what it is and where it is used.

## Layout

All little-endian (the EE and IOP are both little-endian MIPS). Offsets are from
the start of the file.

```
member      2048-byte aligned
  u8[10]    gzip header          1f 8b 08 08 ...
  char[]    name                 NUL-terminated, as in the gzip FNAME field
  ...
```

## Fields

`name` - ... what is known about each field that the table cannot say.

## Notes

Quirks, engine behaviour that depends on the layout, and things a
re-implementation must preserve bug-for-bug.

## Unknown

A list, or "nothing". Never leave this section out - an empty one is a claim,
and a missing one is a silence.
````

Give a worked example when the layout is at all subtle: a real hexdump from a
real entry with the fields labelled. Use a file that is actually on the disc and
name it with its volume, so the example can be re-checked.

## An engine page

Lead with what the subsystem does and the entry points: the function VAs, the
globals it owns, the overlay it lives in. Then the data flow. Name functions by
what they do, and give the VA every time; the binaries carry no symbols we can
trust until a page says otherwise.

## Rules

- No emojis.
- Exact constants. Offsets in hex, sizes in decimal, and say the endianness once
  at the top of the layout block.
- Every structure field gets a type and a name, even when the name is
  `unknown_0c`. Numbered unknowns beat leaving a gap in the table.
- Distinguish measured from inferred. "All 4,341 members have this" is a
  measurement; say the sample size. "This is probably a flag word" is inferred;
  say so.
- Never write aspirational documentation. Docs describe what has been observed
  in the data or in the binary, not what a tool or a port intends to do.
- One thing per page. If a page grows two subjects, split it.
- Cross-link with relative paths: `[the overlay header](prg.md)`.
- Run `tools/docs.py check` before finishing: it catches missing front matter,
  an unknown status or volume tag, a stale index, and a dead relative link.
